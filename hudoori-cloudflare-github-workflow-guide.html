العلاقة بين مجلد المشروع وGitHub وCloudflare

هذا الدليل يوضح أين توجد النسخة الأصلية من ملفات الموقع، وكيف تنتقل التعديلات من جهازك إلى GitHub، ثم كيف يقوم Cloudflare ببناء الموقع ونشره تلقائيًا، وماذا تفعل عند تعديل أي جزء من هذه المنظومة.

مجلد المشروع على الجهاز مكان العمل والتحرير والتجربة المحلية.
GitHub المستودع المركزي وسجل الإصدارات والنسخة الاحتياطية.
Cloudflare يبني الموقع من GitHub وينشره على الرابط العام.
الصورة العامة مصدر الحقيقة التحديث المعتاد تعديل GitHub تعديل Cloudflare جهاز جديد حل الأخطاء الأوامر قواعد مهمة

1. الصورة العامة

مجلد المشروع على جهازك
←
مستودع GitHub
←
Cloudflare Workers

التسلسل الطبيعي يبدأ من جهازك: تعدّل الملفات، تختبر الموقع محليًا، ثم ترسل التغييرات إلى GitHub. بعد وصول التغييرات إلى الفرع الرئيسي main يقوم Cloudflare تلقائيًا بتشغيل أمر البناء npm run build ثم ينشر محتويات مجلد dist.

الرابط المنشور الحالي:
https://hudoori-smart-pro-website.khmobgm.workers.dev

2. ما هو مصدر الحقيقة؟

مصدر الحقيقة العملي هو مستودع GitHub على فرع main، لأنه النسخة التي يعتمد عليها Cloudflare في النشر. أما مجلد الجهاز فهو نسخة العمل المحلية التي تُجرى فيها التعديلات قبل رفعها.

المكانوظيفتههل يعدّل مباشرة؟
مجلد المشروع على الجهاز التحرير، التجربة، البناء، مراجعة الملفات. نعم، وهو المكان الموصى به.
GitHub حفظ السجل، مشاركة الكود، تشغيل النشر التلقائي. يمكن، لكن التعديل المحلي أفضل.
Cloudflare البناء والنشر والاستضافة وإظهار الموقع للعامة. لا تعدّل ملفات الموقع من داخله.
لا تعدّل ملفات موقع الإنتاج مباشرة داخل Cloudflare. التعديل الصحيح يكون في مجلد المشروع، ثم GitHub، ثم النشر التلقائي.

3. ماذا أفعل عند تعديل الموقع من جهازي؟

افتح مجلد المشروع في VS Code أو محرر النصوص.
شغّل الموقع محليًا: 
npm run dev
ثم افتح الرابط المحلي الذي يظهر، وغالبًا: 
http://localhost:5173
نفّذ التعديلات واختبر الصفحات على الكمبيوتر والجوال.
اختبر نسخة الإنتاج: 
npm run build
يجب أن ينتهي الأمر دون أخطاء وأن يتكوّن مجلد dist.
راجع الملفات المعدلة: 
git status
git diff
احفظ التغييرات في Git: 
git add .
git commit -m "Update website content and design"
git push
انتظر حتى يكمل Cloudflare عملية البناء والنشر، ثم افتح الرابط العام وتحقق من التحديث.
مثال: عدّلت عنوان الصفحة الرئيسية.
بعد الحفظ والتجربة محليًا، تنفذ git add ثم git commit ثم git push. بعد دقائق قليلة سيظهر العنوان الجديد على رابط Cloudflare.

4. ماذا أفعل إذا عدّلت ملفًا مباشرة في GitHub؟

يمكن التعديل من واجهة GitHub، لكن يجب بعد ذلك مزامنة مجلد جهازك حتى لا يصبح قديمًا.

احفظ التعديل في GitHub باستخدام Commit إلى الفرع main.
Cloudflare سيبدأ النشر تلقائيًا.
على جهازك افتح PowerShell داخل المشروع ونفّذ: 
git pull
شغّل الموقع محليًا وتأكد أن النسخة أصبحت مطابقة.
لا تنفذ git pull إذا كانت لديك تعديلات محلية غير محفوظة. نفّذ أولًا git status، ثم احفظ تعديلاتك في Commit أو استخدم Stash عند الحاجة.

5. ماذا أفعل إذا غيّرت إعدادًا في Cloudflare؟

التغييرات في Cloudflare نوعان:

أ. تغييرات لا تتطلب تعديل ملفات المشروع

  • ربط نطاق مخصص.
  • تغيير إعدادات Analytics أو Logs.
  • إضافة متغير بيئة غير سري للبناء.
  • إعادة تشغيل آخر عملية نشر.

ب. تغييرات يجب توثيقها داخل المشروع

  • تغيير أمر البناء.
  • تغيير أمر النشر.
  • تغيير اسم Worker.
  • تغيير مسار مجلد الملفات الثابتة.
  • إضافة متغيرات يعتمد عليها الكود.

عند تغيير أي عنصر من النوع الثاني، حدّث ملف wrangler.jsonc أو package.json داخل المشروع، ثم ارفع التغيير إلى GitHub حتى تبقى الإعدادات موثقة وقابلة للاستعادة.

مثال: إذا تغيّر مجلد الإخراج من dist إلى اسم آخر، يجب تعديل assets.directory داخل wrangler.jsonc، وليس تعديل Cloudflare فقط.

6. ماذا أفعل عند الانتقال إلى جهاز جديد؟

ثبّت Git وNode.js وVS Code.
انسخ المستودع: 
git clone https://github.com/alharbikh/HudooriSmartPro-Website.git
ادخل إلى المجلد: 
cd HudooriSmartPro-Website
ثبّت الحزم: 
npm install
شغّل الموقع: 
npm run dev

لا تحتاج إلى نسخ مجلد node_modules من الجهاز القديم، لأنه يُعاد إنشاؤه عبر npm install.

7. ماذا أفعل عند حدوث خطأ؟

Cloudflare لم ينشر آخر تعديل

  • تحقق أن git push نجح.
  • تحقق أن التغيير وصل إلى فرع main في GitHub.
  • افتح Cloudflare ثم سجل البناء وافحص رسالة الخطأ.
  • شغّل محليًا npm run build لمعرفة إن كان الخطأ قابلًا للتكرار.

الموقع يعمل محليًا لكنه لا يعمل بعد النشر

  • تحقق من المسارات النسبية للصور وCSS وJavaScript.
  • تأكد أن الملفات المطلوبة تدخل إلى مجلد dist.
  • تأكد أن اسم الملف وحالة الأحرف متطابقان؛ خوادم Linux حساسة للأحرف.

حدث تعارض بعد git pull

لا تحذف الملفات عشوائيًا. افتح الملفات المتعارضة، اختر النسخة الصحيحة، ثم: 

git add .
git commit -m "Resolve merge conflicts"
git push

أريد الرجوع إلى إصدار سابق

استخدم سجل GitHub لتحديد الـ Commit الصحيح. الأفضل إنشاء Commit جديد يعكس التغيير بدل حذف التاريخ. عند الضرورة يمكن استخدام: 

git revert <commit-hash>
git push

9. قواعد تشغيل يجب الالتزام بها

  • عدّل الموقع من مجلد المشروع المحلي كلما أمكن.
  • اختبر محليًا قبل كل Push.
  • نفّذ npm run build قبل رفع تعديل مهم.
  • اكتب رسالة Commit واضحة تصف النتيجة.
  • لا ترفع كلمات مرور أو مفاتيح سرية إلى GitHub.
  • لا تعدّل Cloudflare بطريقة تخالف ملفات الإعداد الموجودة في المشروع.
  • بعد كل نشر، اختبر الصفحة الرئيسية والروابط الأساسية من الرابط العام.
  • احتفظ بفرع main دائمًا في حالة قابلة للنشر.
قاعدة مختصرة:
عدّل محليًا → اختبر → ابنِ → Commit → Push → راقب Cloudflare → اختبر الموقع العام.
