النطاق والهدف

هذه المرحلة لا تبني نظام حضور جديدًا، ولا تنقل بيانات حضوري التشغيلية إلى السحابة. هدفها إنشاء منصة خلفية آمنة لإدارة حسابات مستخدمي تطبيق حضوري سمارت برو، والخطط، والاشتراكات، والأجهزة، وفحوص الترخيص، والإصدارات، والإعدادات، والصيانة، والتدقيق.

المبدأ الحاكم: Local First + Cloud License — البيانات التشغيلية تبقى على الجهاز، بينما تدير Supabase الهوية والترخيص والاشتراكات فقط.

الأمان وRLS

ما تم تنفيذه
  • تفعيل RLS على الجداول الحالية.
  • سحب صلاحيات anon وauthenticated مؤقتًا.
  • عدم وضع service_role في Flutter أو المتصفح.
  • فصل حساب HSP عن جلسة حضوري الرسمية.
ما لم يُنفذ بعد
  • سياسات RLS النهائية لكل دور وجدول.
  • Grants النهائية المتوافقة مع RLS.
  • وظائف Edge Functions الفعلية.
  • JWT validation وRate limiting العمليان.
تفعيل RLS وحده لا يكفي. الوصول سيظل مقيدًا حتى تنفيذ Migration 008 الخاصة بالـGrants والسياسات النهائية.

القرارات المعمارية والتجارية المعتمدة

المجال القرار
ملكية الاشتراكاشتراك فردي لمستخدم واحد في الإصدار الأول، ودعم المدرسة مستقبلًا.
مصادقة HSPبريد إلكتروني وكلمة مرور مع تأكيد البريد.
مصادقة حضوريمنفصلة بالكامل داخل WebView الرسمي ولا تشارك جلسة مع HSP.
التجربة14 يومًا، مرة واحدة لكل حساب ومرة واحدة لكل جهاز.
معرف الجهازinstallation_id عشوائي، وليس IMEI أو MAC أو Android ID.
حد الأجهزةمستمد من الخطة، مع استبدال جهاز يختاره المستخدم.
بعد انتهاء الاشتراكتبقى القراءة والتعديل المحليان متاحين، ويُمنع الاستيراد.
التسجيليمكن فتحه أو إغلاقه عن بعد عبر registration_enabled.
الدفعGoogle Play والموقع الإلكتروني مستقبلًا، وليس ضمن التنفيذ الحالي.
لوحة الإدارةمطلوبة، والعمليات الحساسة تمر عبر Backend موثوق.
